Docker Fundamentals

A hands-on course in containers for developers who build AI web apps. You take one small Python service, put it in a container, make it safe to ship, give it a database and a real model, and follow it to AWS, Cloudflare and Kubernetes.

The lessons use Podman, a free tool that works like Docker. The ideas are the same, and most commands work with docker in place of podman.

Who it is for

  • You can read Python and use a terminal.
  • You have not used Docker or Podman, or you have copied commands without knowing what they do.
  • You have a Mac with Apple silicon. Every output in the lessons comes from one.

If you use Docker and not Podman: the outputs shown are Podman's, and a few steps are Podman-only, such as --format docker in Lesson 3 and the way Lesson 7 loads images into kind.

Before you start

1. Install the tools

With Homebrew:

brew install podman jq docker-compose
  • podman builds and runs containers.
  • jq picks values out of JSON. Lesson 3 uses it.
  • docker-compose is the program that podman compose hands its work to. Lesson 4 uses it.

2. Create Podman's Linux VM

Containers need a Linux kernel, so on a Mac Podman runs them in a small virtual machine. Lesson 1 explains why. Create it once, then start it:

podman machine init
podman machine start

3. Get the practice apps

The lessons work in ~/practice/hello-ai and ~/practice/hello-model. Copy the starting files there:

git clone https://github.com/Espad0/docker-fundamentals.git
mkdir -p ~/practice
cp -R docker-fundamentals/starter/hello-ai docker-fundamentals/starter/hello-model ~/practice/

The same repository has a solutions folder with the finished files of each lab.

Not re-run

The install commands in steps 1 and 2 are the standard ones, but they were not run again for this course, because the test Mac already had the tools. The copy command in step 3 was tested.

How it was made and tested

This course was written with Claude, Anthropic's AI model, in September and October 2026. Every command that runs locally was run on one Mac before it went into a lesson.

That Mac is the test Mac in the lessons. Outputs, sizes and timings come from it, so yours will differ a little.

What was not run

  • The AWS and Cloudflare account steps in Lesson 6. They are written from the providers' documentation, checked on 28 September 2026. Everything local in that lesson was run, including the build job and a Cloudflare dry run.
  • The AWS parts of Lesson 7. The production files (an ECR image, an Ingress for an AWS load balancer, a secret from AWS Secrets Manager, the IAM policy) need an EKS cluster. They were only checked against the local cluster without being applied. Everything else in that lesson ran on a local kind cluster.
  • Network rules in Lesson 7. The local cluster did not enforce them in a quick test, so the lesson only describes them.
  • One Docker-only rule about volumes in Lesson 4. The test Mac has Podman only.
  • Outputs of a rootless Podman machine. The test Mac's is rootful.

Versions move. Package versions, image sizes and the base-image digests in the lessons are from autumn 2026, and the lessons show how to look up current ones.
